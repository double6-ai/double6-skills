## 必须做

1. 无头截图，不抢用户正在用的 Chrome。
2. 至少覆盖桌面和手机的：首页、确认/先看页、作答页（含选项）。不要只截首页。
3. 用读图方式打开 PNG，不要只看文件名或 `font-size` 数字。
4. 把看到的问题写成 finding：症状、哪一屏、为什么 CLI 会漏。
5. 字号够大但字被卡片裁切，算失败。
6. 分栏首页里的子卡必须按卡片自身宽度重排，不能只看浏览器 viewport。状态、按钮或提示语被压成逐字竖排，即使没有触发整页横向滚动，也算文本溢出失败。

## 眼睛要查的

- 选项字、题图、emoji 是否完整露出来，有没有被框切掉。
- 题图是不是题意里的那个东西（文案写小象，图却是长颈鹿）。
- 首页说明是否还在说已经改掉的旧规则（例如已经一组连做，仍写「各一题」）。
- 四档是不是真的不像同一张脸，还是只换了标题、房间图仍是同一构图。看首页主图：房子形状、机位、场景必须一眼不同。
- 伙伴文案和画是不是同一角色；授权 IP 名不能出现在原创角色上。
- 伙伴卡文案说饿了/在等时，图是不是也在等，不能仍是一张笑脸。做完三站后图必须换成好了。
- 文案写「怪兽在远处晃」时，卡片上必须能认出小兽，不能只是勇士脸部特写。远处不等于看不见。
- 房间门牌是不是「我的小花园」或「乐乐的小花园」。首页是不是先看见今晚三站和还在等他的伙伴，而不是一排要摆的小物件。
- 连续打开三天后，首屏伙伴卡是不是和第一天不一样：近三日三格有来过痕迹，第三天有「这几天都见到你了」，但没有「连续 N 天」数字格子，今天三站仍在首屏。

成人台额外必看：每一个侧栏。已选房间都要在侧栏里，点进去都要有活。考公要有计划、今天科目、做题、错题、素材；首页三扇门必须一眼分得出行测卷、申论稿纸、面试计时，不能是三颗同色按钮；计划不能和今天科目抢同一张卡，错题至少三道不同考点，素材必须有可写的申论面，不能只看提纲。手机第一屏必须看见问题写作框，材料不能把框挤下去。记账要有流水、凭证、税、复盘、审计。凭证不能冒出收支演算，复盘判断缺票，审计判断重复票，两房不得同题。首页能记一笔或做一题，不等于这些房间可以删。打开后只有「查看内置示例详情」和摊开的「完整操作区」，这一刀失败。记录表单要收在「自己要留的记录」里，第一屏是今晚的活。第一道题、第一张卡必须像这个人今晚的工作：考公不能是小学生近义词，记账演算不能把收入支出写成数值 1 / 数值 2。房间眉题要说今晚的活，不能写「待完成的小事」；开箱卡上不能再放「查看详情」。开箱卡顶不能写「先从这里开始 / 可反复练习」，要说打开就能做。开箱卡上不能写「小任务 / 完成这一项 / 可编辑模板 / 标记已查看」，按钮就是勾掉、按这个改、看过了。手机做题选项和下一张卡不能被吸底动作条挡住。首页绿条不能再放「做这一题」，题和提交就在下面。计划三块必须是一条今晚 60 分钟时间表，带序号和时段，不是三张开箱卡。第一屏只留这张表，不要再在下面放「今晚只有 60 分钟」判断题。题型条手机必须单行，多了就横滑。首页和做题房必须是同一张刷题卷：题型条看得见，提交后对错和正确答案马上标出来。卷面上有听这题；朗读不能是刺耳的系统默认声。英文词卡必须用英文声读单词，不能把旁边的中文注释读进去。科目是去做这一科，不能再并排勾掉。错题房也是卷，不能写打开就能做。素材是今晚写申论。科目写「去做题」时，必须落到对应考点的那一题，不能只打开做题房第一题。记账首页流水应是空账，不能已经有晚饭 29.90。记账首页隐私条不能再把「不是银行余额 / 不是已申报」当壁纸。首页不能出现「内置内容 / 自有记录」这种制作器内部词。

成人主题在设计阶段锁定后，仍必须检查派生文字色，而不只看 registry 里的背景色：浅色侧栏上的产品名和未选 Tab、主色底上的选中 Tab，文本对比度都必须至少 4.5:1；构建时 `sidebar-ink` 与 `primary-ink` 必须按已选背景计算，不能沿用模板的白字。Hero 左侧是浅色遮罩时必须用深色文字；只有明确使用深色遮罩的主题才能用白字。浏览器证据必须记录成品的实际 computed color/background 与对比度，并断言成品没有主题选择器、切换脚本或 UI 偏好键。其余主题由 registry/资产 SHA 和设计阶段编译测试覆盖，不要求同一页面运行时切换。

走查结束必须留下用户没提过的 finding。没有未点名问题就重走，不能把页交出去。

## 不算视觉检查

- 元素存在、按钮可点、`data-*` 对得上。
- `getComputedStyle` 字号大于某阈值。
- 只看首页、或只看桌面。
- 只确认「不是真题」「不是银行余额」等边界句，不打开侧栏、不读第一题。
- 检查器全绿，但第一屏仍是工作台壳：绿条「做这一题」、三张开箱卡、计划下面再跟判断题。
- 看样例页时不读左上角产品名，结果把「走查工作台」当成场景名。

儿童入口/题量/题图的机器审查仍跑 `check_child_review_invariants.py`。目视审查补的是机器看不出的那一层。

上一轮已沉进 Skill 的门：题图先取故事角色、短选项按卡片缩放、学段文案不得写「各一题」、可见文案不得写「奥特曼」、四档房间主图必须是不同构图并锁哈希、伙伴卡按在等/好了换图并锁哈希、房间门牌能写称呼并放一件自己的东西。改完仍须看图，检查器过了不等于画面对。

## 问题什么时候才算解决

检出或修好的问题，不能停在某份 iteration HTML。必须先写清根因（合同、渲染、题库、皮肤文案还是审查门漏了），再回写本 Skill：

- 规范进 `references/` 或 `SKILL.md`
- 能反复犯的写成 `review-invariants` / `content-mines` 检查器
- 运行时修在 `scripts/double6_runtime/` 或内容包，让下一次 `build` 带上

只改预览页、只记 receipt、或聊天里修完，都不算解决。用当前 Skill 重建一页后问题还在，就是没沉下去。
