# 工作台题目排雷（可复用）

用户指出的不是零散笔误，而是几类会反复出现的内容雷。**儿童题和其它场景的题目都会犯**：标题泄题、答案总在第一项、选项对不上、故事和问题拆页。以后改任何场景的题库或作答页，先跑检查，不要再让人一题一题扫。

内容真值（对错、守恒、看图）仍走 `content-truth-review.md`。这里只管**已经炸过、还会再炸**的交互和题面雷。

## 什么时候跑

改 `scene-capability-starters.json`、`education-stage-starters.json`、作答页或重建待审页之后必跑：

```bash
python -B scripts/check_content_mines.py
```

儿童乐园入口、题量、题图、房间等已提问题仍跑：

```bash
python -B scripts/check_child_review_invariants.py
```

儿童审查里的 `content_mines` 也会扫全部场景题目。活动测试和发布门核对本文件与检查器存在。跨场景邻域词和假提交语气另跑：

```bash
python -B scripts/check_domain_remnants.py
```

班主任开箱种子另见 `teacher-tonight-content.md`，跑 `python -B scripts/check_teacher_class.py`。

只看首页截图、或只跑旧通过项，不算已经排雷。成人台还要打开每一个侧栏：已选房间都在、点进去有活；演算框必须是收入/支出这类词，考公第一题不能是近义词，模块页不能把工作收进「查看内置示例详情」。科目「去做题」必须落到对应考点。申论必须能当场写，不能只看提纲。记账开箱不能预填晚饭流水。不得靠收侧栏提高「干净度」。

## 覆盖范围

- `references/scene-capability-starters.json`：Scene 00–15 里所有 `kind=question`
- `references/education-stage-starters.json`：宝宝、一升二、二升三、三升四学段题
- 交给页面之前必须走 `serve_question` / `place_answer`，不能按作者草稿把答案全放第一项

儿童乐园的作答页、练一练入口另查源码。一升二冻结 SHA 不原位改写。

## 雷的类型

| 类型 | 适用 | 判定 | 不是这类雷 |
| --- | --- | --- | --- |
| 答案总在第一项 | 全部选择题 | 同一场景同一知识点 ≥4 题，正确答案不能全在第一项 | 单题碰巧在第一项；填空/数字题 |
| 标题泄题 | 全部选择题 | 作答页标题不能写出答案，包括一个字的字卡 | 词汇题标题是题干词、答案是释义；短文里作为材料出现的词 |
| 只有答案带图 | 全部选择题 | 要么每个选项都有图，要么都没有；不能只给正确答案配图 | 找不同题四个都有图，靠类别区分 |
| 答案不在选项里 | 全部选择题 | 答案必须能点到 | 数字/文本输入题 |
| 答完铺题名 | 儿童 overlay | 答完只出「下一题」或「回去」 | 题库页按做过记录浏览 |
| 练一练开做前铺题名 | 儿童 overlay | 练一练、观察页只留当前一题 | 一升二正式 104 题学科页仍可收起「还想玩」 |
| 故事和问题拆页 | 儿童数量题 | 有数量变化的故事必须和问句、选项、数量图在同一页 | 两位数乘法不必画出几十个物件 |
| 声母对不上 | 儿童声母题 | 探测词和答案开头必须一致；不能用「A和B」标题 | 大小比较等成对事物本身就是题目 |
| 题图泄答案 | 儿童 overlay | 上方题图不能是答案的图，也不能从答案字段选图 | 数字题的饼干图不是答案 |
| 一组做完循环 | 儿童 overlay | 下一题只找还没做过的同组题；本组做完停住，回首页或先问要不要再玩 | 不得自动跳进下一组，也不得把已做过的题再从头循环 |
| 组内进度 | 儿童 overlay | 作答页显示 n/6，家长能看见做到第几题 | 不得只写「还有几题」却没有数字 |
| 数量图画错物件 | 儿童数量题 | 画被数的饼干/积木/小鸟，不能画盘子、篮子 | 容器只出现在文字里 |
| 题图对不上故事 | 儿童 overlay | 故事里有在场角色时，题图必须是那个角色，不能先吃引号里的「高」「妈妈」 | 没有角色的抽象题可用知识点图或兜底图 |
| 选项大字被裁 | 儿童 overlay | 短选项必须按卡片缩放；写死 136/168px 算失败 | 桌面上看起来大、手机上完整露出都要成立 |
| 首页还写各一题 | 儿童四档 | 一组连做之后，学段文案不得再写「各一题」 | 确认页写「这一站有 8 题」不是这类雷 |
| 可见授权 IP 名 | 儿童激励 | 可见标签和心情文案不得写「奥特曼」；暮光小屋用光之勇士 | 内部 id `companion-ultraman` 可以保留 |
| 房间同一张构图 | 儿童四档首页 | 主图文件、哈希、房子、机位、场景必须都不同 | 只换配色或宠物不算不同构图 |
| 伙伴卡说饿了仍是笑脸 | 儿童伙伴卡 | 四种皮必须有 waiting / well 两张不同哈希图；hopeful/almost 复用 waiting | 身份半身照只作兜底，不能当心情图 |
| 怪兽在晃却看不见 | 光之勇士在等图 | waiting 必须是双人中景，visible_cast 含小兽；108px 卡片上能认出 | 不能用地平线一个点或勇士特写代替 |
| 房间不像我的 | 儿童四档首页 | 门牌能写称呼；没名字仍是「我的<房间>」 | 不能上传照片，不能写授权 IP 名 |
| 把摆件当主活动 | 儿童四档首页 | 首页不得再出现摆件选择条或拖动物件 | 小朋友要今晚三站和还在等他的伙伴 |

检查的是类型，不是某一道题的特例。旧雷（「宝宝和包子」「弟弟配大象」「黄色当标题」「答案全第一项」）写在测试夹具里，写回去会先红。

## 怎么加一类新雷

1. 用用户原话登记到 `review-invariants.json`（儿童交互）或写进本表（通用题面）。
2. 在 `content_mines.py` 写可判定检查：输入是题目或作答页源码，输出错误字符串。
3. 先让检查器在旧代码上失败，再改产品。
4. 在测试里加一条旧雷夹具。
5. 把判定补进本表。新场景只要往 starter 合同里加 `kind=question`，就会被扫到。

禁止：聊天里修完就走；只改这一道题、不收成类型；只扫儿童题、假装其它场景不会犯。
