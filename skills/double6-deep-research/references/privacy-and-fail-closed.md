# double6-deep-research 隐私与 Fail-closed

## 凭据与运行边界

- 不读取、索取、复制、记录或回显 env、dotenv、Keychain、token、cookie、API key 或原始 credential。
- 不保存或要求 endpoint、model、provider、proxy、transport、retry、认证或计费配置。
- 不实现 API client、adapter、runner、retriever、multi-agent runtime 或外部工具连接。
- 只调用宿主已提供且用户明确允许的能力；宿主能力不可用时停止对应步骤。
- 随附 validator 只读取 bundle 内文件并写入本地 `validation_receipt.json`；它不启动
  subprocess、不访问网络，也不安装依赖。安装环境没有专用安全审计 skill 时，可以
  逐文件审查和静态扫描，但不得把“审计工具缺失”误写成研究能力失败。

## 来源与事实边界

- 把不可访问、内容不完整或身份不明的来源标记为 unavailable、partial 或 uncertain。
- 不把 README、营销声明、搜索摘要、文件存在或宿主成功状态冒充真实效果证据。
- 不生成包外引用，不把推断写成事实，不掩盖冲突、缺口或失败。
- 发现疑似 secret、未授权个人数据或越权材料时，停止处理相关内容并请求用户净化或授权。
- 不绕过登录、付费墙、robots、访问控制或网站明确限制；不能合法读取的材料只登记为不可访问。
- 默认不保存整页受版权保护正文；只保留完成核验所需的最小摘录、定位和哈希。用户提供的私有材料不得写入公开 bundle。
- 不保存完整查询轨迹或候选来源全集；只保留逐问题覆盖要求、采用来源、检查策略和结论影响。
- 快照路径必须位于当前 bundle 内；拒绝绝对路径、`..` 越界路径和解析后逃逸 bundle 的
  符号链接，避免把本机其它文件误读为研究证据。

## 高风险决策

- 医疗、法律、金融、合规和人身安全问题优先使用监管机构、法律原文、正式医学资料或同等级权威来源。
- 报告和 `research_record.json` 必须明确事实截止日、适用地域、关键未知和需要专业人士复核的事项。
- 不把研究报告写成诊断、法律意见、投资保证或自动执行授权；证据不足时缩小结论或交付 `partial`。

## 能力与结论边界

- 不声称本 Skill 自带搜索、抓取、原生检索、多 agent、exact-once transport 或 provider 能力。
- 不声称存在推荐候选、胜者、相对收益、ROI 或上游能力不足。
- 不把实验性 project-local 创建写成标准五门通过、安装、共享、发布或生产就绪。

## Fail-closed 输出

遇到以下任一情况时，停止对应研究步骤并显式报告：

- 没有获准的宿主搜索／网页工具；
- 核心结论所需证据不可访问、没有可接受替代来源，且无法闭合 claim-source 绑定；
- 输入范围、来源角色或数据授权不清；
- 需要读取凭据或配置 provider 才能继续；
- 交付将不可避免地引入包外事实、隐藏假设或未披露冲突。

单个非核心来源不可访问时，保留为 gap 并继续其它可独立成立的部分；不要把局部失败自动
扩大成全局 `blocked`。真正触发上述条件时，把 `research_status` 标为 `blocked`，只交付
已知事实、研究计划、未完成项、风险和解除条件；不要声称已检索、已验证或已完成。
