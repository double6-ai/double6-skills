# 常规 OCR 路线（`candidate --route scanned_ocr`，2.0.0-rc.8）

本路线把**受支持**的扫描页/混合 PDF 交给本地 Tesseract 识别，重建成“干净背景图 + 可见 OCR 文字层”的源 PDF，然后交给既有电子 PDF 后端。电子路线的所有守门照常执行：重建源电子预检（`require_digital`）、`route_pdf`、渲染残留、综合质量门、严格交付。任何不受支持的版式在**模型调用之前**以退出码 2 和下列稳定错误码拒绝。

OCR 文字是机器输出，没有经过人工逐字核对，所以**永不作为质量验收**：
- `OCR_MANIFEST.quality_claim = none`；
- 工作流回执 `ocr_text_layer_is_acceptance=false`；
- 综合质量最高记为 `unverified`（原结论另存于 `quality_status_before_ocr_cap`），`fail` 保持 `fail`；
- `quality_pending` 加入 `ocr_text_unverified`。

## 流程

1. **引擎检查**：需要 `tesseract` 与 `chi_sim`、`eng`、`osd` 语言数据。缺失时只阻断本路线（`ocr_engine_unavailable`，退出码 2）。`doctor` 只报告引擎状态（`blocks_routes: ["scanned_ocr"]`，`blocks_digital_route: false`），不进入电子路线的阻断项。
2. **有界 OCR 重建**：`ocr_route.py` 作为 `run_bounded` 的任务运行（操作名 `ocr-reconstruct`，0.5 s 采样）。
   - 每个 `tesseract` 都是它的直接子进程，进程树与后端一样：计入同一任务内存，记录 PID 与 create_time，带启动 nonce、父链核验，超限或超时整树回收。
   - 未核实的进程不报告为已确认。
   - OCR 与随后的后端共享 FREEZE 资源合同里的同一个单任务时限（`per_job_seconds`）。
   - 每次调用另设 45 s 的单进程上限，超时即杀并以 `ocr_engine_failed` 拒绝。
3. **逐页处理**：
   - 原生文字页原样复制。若页内有大图且图中 OCR 出 ≥20 个可信词，按页内混排拒绝。
   - 扫描页依次经过：300 dpi 渲染 → 分辨率门 → 框线门 → OSD 方向 → 版面分析与识别（`--psm 3`）→ 碎行重识别 → 弱词多遍核验 → 分类与版式门 → 上下标/叠排分式几何门 → 覆盖原文字 → 背景残留复查 → 写回文字层。
4. **重建源绑定**：`OCR_MANIFEST.json` 记录输入 sha256、引擎与语言数据 sha256、阈值、每个 tesseract 进程的身份与峰值 RSS、逐页结论，以及重建源的路径和 sha256。
   - `_execute-digital --ocr-manifest/--ocr-manifest-sha256` 在后端子任务里逐 sha 核对三件事：清单本身、清单里的输入 = FREEZE 输入、后端输入 = 清单里的重建源。

## 支持 / 拒绝矩阵

| 维度 | 支持 | 拒绝（错误码） |
| --- | --- | --- |
| 语言 | 简体中文源（`chi_sim+eng`，中译英）；英文源（`eng`，英译中） | OCR 文本语言与声明的源语言不符：`ocr_source_language_mismatch`；竖排文字：`ocr_vertical_text_unsupported` |
| 整页扫描 | 每页一张整页图像、横排单栏或规整双栏正文 | 图像拼贴（多块图像拼成一页）：`ocr_tiled_scan_unsupported`；矢量轮廓字（无文字层，≥5000 个绘图项）：`ocr_outlined_vector_text_unsupported` |
| 混合文档 | 原生文字页 + 扫描页按页混合（原生页原样保留） | 同一页内原生文字与扫描文字混排：`ocr_mixed_within_page_unsupported`；全是原生页：`ocr_route_no_scanned_pages`（请用 `digital_pdf`） |
| 旋转 | 0/90/180/270°：页面 `/Rotate` 或 OSD 判定，且 OSD 置信度 ≥ 3.0 | OSD 判定需要旋转但置信度不足：`ocr_orientation_uncertain`；倾斜 > 1.0°：`ocr_skew_unsupported` |
| 分辨率 | 源图有效分辨率 ≥ 200 dpi（容差 0.97），且正文中位行高 ≥ 18 源像素 | `ocr_resolution_too_low` |
| 表格 | — | 框线表格或带网格的图表：≥3 条长水平线且 ≥2 条长竖线，方向对称判定，在 OSD 之前检查；无框线表格：≥3 行各有 ≥2 个大于 2 倍行高的列间隙。两者都报 `ocr_table_unsupported` |
| 公式 | 行内斜线分式（`a/b`、`M/N`）按普通文字原样保留 | 识别出的数学行（运算符/希腊字母密度、`x = …`、行末公式编号）：`ocr_formula_unsupported`。图像里的上标/下标（`x²`、`10⁻³`、`H₂O`、`x_i`、脚注上标号、上标序数词）和叠排分式：同一错误码，`details.evidence = image_geometry`，见下节。不删公式、不遮挡正文 |
| 置信度 | 页面平均词置信度 ≥ 80（英）/ 75（中），不确定行 ≤ 2 且不确定字符 ≤ 3% | `ocr_low_confidence`；没有任何可信文字：`ocr_no_reliable_text` |
| 背景 | 文字所在处背景均匀（灰度 p90−p10 ≤ 60，彩色 ≤ 5%，暗像素 ≤ 8%） | 文字压在图形、印章、彩色底纹上：`ocr_text_over_graphics_unsupported`；覆盖后背景仍可 OCR 出可读文字：`ocr_background_text_residue` |
| 引擎 | Tesseract 5.x CLI | 缺失：`ocr_engine_unavailable`；超时或非零退出：`ocr_engine_failed` |

页数仍受首发上限约束（1–5 页），不做长文档分块。

## 上下标与叠排分式（图像几何门）

OCR 常把上标读成别的字符（实测 `x²` → `x?`，`10⁻³` → `10°`，脚注上标 `1` → `'`），文字里已没有数学证据，文字门（上一节的数学行判定）因此放行。本门在**覆盖原图之前**只看渲染图像的几何，任一行有无法解释的上下标字形或页面有叠排分式，整页以 `ocr_formula_unsupported`（`details.evidence = image_geometry`，`details.samples` 记录行、基线、x 高与每个可疑字形的位置和理由）拒绝，不改写、不删除。

复用：
- 电子路线 `pdf_input_preflight._math_like_glyphs` 的判据——字号比超出 0.75–1.33、相对同行基线偏移的孤立字形算数学字形。扫描页没有字体信息，改为下面的像素量化；
- 本文件框线门已有的二值化与 OpenCV 连通域（依赖已在锁文件中）；
- tesseract TSV 的逐词框与文字（`word_boxes` / `word_texts`，碎行重识别与多遍核验采用的结果同样携带）。

逐行做法：
1. 行框外扩 0.25 行高后二值化（阈值 `min(160, p90 − 60)`），取中心落在本行内的连通域；横向重叠 > 50% 的连通域并成字形簇（i/j 的点、重音、汉字的分离部件并入同一簇）。宽 < 3 px 或 < 0.15 x 高的簇（扫描发丝线）不计。
2. 基线 = 各簇底边的中位数；x 高 = 底边贴近基线的簇高度的第 30 百分位。
3. 抬高簇：底边高于基线 ≥ 0.35 x 高，顶边 ≥ 1.15 x 高，簇高 ≥ 0.45 x 高。压低簇：顶边 ≤ 0.75 x 高，底边低于基线 ≥ 0.25 x 高，簇高 ≥ 0.45 x 高。
4. 只有天然处于该位置的标点能解释它：抬高簇须是小而窄的记号（高 ≤ 0.72、宽 ≤ 0.8 x 高），且所属词（词框内或 2 x 高内的最近词）里 OCR 读出了足够数量的引号、撇号、`*`、`°`（`"` 计 2 个）；压低簇须顶端 ≤ 0.5 x 高，且所属词里有不夹在两个字母数字之间的 `,` `;` `，` `；` `、`（`H,O` 中间的逗号不算）。单个变量或数字（≤2 个字母数字）旁的抬高记号（`x'`、`1‘`）不算解释。其余（读成 `?`、数字、被丢掉、不在任何词旁）都算上下标证据。
5. 含汉字的行（PR #20 review 2 改写；此前“靠近汉字词的小部件视为汉字笔画”会把 `估计量甲²` 读成 `甲-`、`甲₂` 读成 `甲,` 并覆盖原图）：x 高取汉字高度，按小字形（0.2–0.6 字高）判定，抬高 = 底边高于基线 ≥ 0.35，压低 = 顶边 ≤ 0.5 且底边低于基线 ≥ 0.15。是否为汉字笔画**不看最近的 OCR 词是不是汉字**（汉字行的 OCR 词框常有偏移，`甲` 的词框会盖住旁边的 `²`），而看汉字方块的规则性：
   - 汉字笔画：高 ≤ 0.4 字高的小簇，与紧邻的 1–2 个簇（相邻间隙 ≤ 0.25 字高）合起来宽 0.75–1.1、高 ≥ 0.75 字高，能拼成一个汉字方块（`估`、`省` 的分离部件，`文` 顶上的点；真实扫描 zh-07 的“部”要左竖 + 点 + 右部三簇才成方块）。高于 0.4 的小簇（9 pt 数字/字母上下标 ≈ 0.45–0.55 字高）即使能拼成方块也不跳过（`文献¹` 的 `1` 与“献”能拼成方块）；
   - 标点解释：汉字行在 ±1 字高窗口内找读出了标点的词；标点形状须吻合——高 ≤ 0.4 字高，抬高记号单个簇宽 ≤ 0.26 字高（引号每撇 0.16–0.19；`n`、`2` ≈ 0.33），压低记号宽 ≤ 0.8；汉字之间的 `，` 照常算解释（`_mark_zone` 只把夹在两个**拉丁**字母数字之间的逗号排除）。每个记号字符只解释一个簇，簇依次归给窗口内还有剩余记号的最近词（`“附录二”` 两侧引号各归各的词）；
   - 落在拉丁/数字词旁（0.5 字高内且最近词就是它）的小字形，基线取该词自身字形的底边中位数（汉字字面常低于拉丁基线）。
6. 粘连上下标（与相邻字形像素相连、并成一个簇，PR #20 review 2 新增）：
   - 拉丁行，上标：簇边缘一段墨迹高出本行升部线（顶边 ≥ 1.2 x 高的簇的顶边中位数，至少 5 个）≥ 0.22 x 高，宽 0.2 x 高 – 0.7 × 簇宽 → 直接算上标证据（没有任何标点处在这个位置）；
   - 拉丁行，下标：宽 ≥ 1.2 x 高的簇，边缘一段连续“纯下标列”（每列墨迹底端低于基线 ≥ 0.2 x 高、顶端在基线上方 0.25–0.75 x 高；`g/p/q` 的列向上到 x 高线，`y/j` 的尾巴整列在基线以下，都不算）→ 按压低簇处理（逗号形状才可解释）；
   - 汉字行，下标：汉字方块（高 ≥ 0.75 字高）左/右边缘一段“纯下标列”（每列顶端 ≤ 0.5、底端低于基线 ≥ 0.1 字高），宽 0.15–0.6、墨迹总高 ≥ 0.4 字高；
   - 汉字行，上标：边缘一段“纯上标列”（每列底端高于基线 ≥ 0.35 字高），宽 0.15–0.6、总高 ≥ 0.4 字高，**且**顶端高出本行汉字方块顶端中位数 ≥ 0.12 字高。
7. 带圈序号（`①`…`⑩`，汉字行，PR #20 review 2 新增）：tesseract chi_sim 会把 `①` 读成 `中`、`@` 等，序号丢失。外圈连通域 0.6–1.15 字高、宽高比 0.8–1.25，圈内另有完整连通域，外框四角（各 0.12 边长）无墨，且圈内连通域之外的墨迹 ≥ 90% 落在归一化半径 0.72–1.05 的环带里、16 个方向都有 → 几何证据（`kind=enclosed`，`details.enclosed_numerals` 计数）。“每”“细”四角也空、也含封闭小部件，但笔画穿过中心，不是环；`口`/`回`/`国` 四角有笔画；`〇` 圈内没有字形。

叠排分式：页面上（只在不含汉字的行附近）一条实心细横线（厚 ≤ 0.18 x 高、长 0.9–8 x 高），其正上方与正下方 0.45 x 高内都有字形，即判为分数线。更长的线由框线门或下划线处理。

局限（宁可拒绝）：
- 脚注上标号与上标序数词（`1ˢᵗ`）同样被拒绝。脚注密集的扫描文献会因此不能走 OCR 路线；
- 单个变量或数字后的撇号（`x'`、英尺/分 `5'`）不作为解释，含这些写法的页会被拒绝；
- 汉字旁的脚注上标号（`文献¹`）与带圈序号（`①②③`，包括列表序号）同样被拒绝：OCR 会丢掉或改写它们（`¹` 被丢、`①` → `中`），宁可拒绝；正文字号的 `［1］` 式序号可以通过；
- 粘连上下标仍有检测不到的情形（几何上与正常字形无法区分，按实测给出边界）：
  - 汉字行上标与汉字像素粘连、且顶端高出本行汉字顶端中位数 < 0.12 字高时漏判。依据：真实扫描 zh-01/02/03 中 2212 个汉字簇最多高出 0.11 字高，而大量汉字边缘本身就是只在上半部的笔画（宽 0.43–0.52、高 0.38–0.67 字高），与粘连的 9 pt 上标（露出宽 ≈ 0.24、高 ≈ 0.49）单看形状无法区分；测试样张中粘连的 `甲²` 高出 0.14，被拒绝；
  - 粘连后露出部分窄于 0.15 字高（汉字行）/ 0.2 x 高（拉丁行）、或拉丁上标没有高出升部线 0.22 x 高（例如紧贴小写字母、且本行升部字母不足 5 个）时漏判；
  - 汉字行里 x 高字母（`r`、`c` 等宽 ≤ 0.26 字高、高 ≤ 0.4 字高）作上标且 OCR 恰好读成引号时，按引号放过；
- 印章压字的页（zh-06）上，红章在灰度阈值下把笔画切断，切出的笔画端头会被当作粘连上下标报出；这类页本来就因识别置信度不足被拒绝，结论不变，但几何门在强干扰页上会多报；
- 阈值按 300 dpi 渲染与常见正文字体标定，没有覆盖手写、强噪点或极小字号的扫描件。

## 不确定行与多遍核验

行内任一可读词置信度 < 50 时，这一行要做多遍核验：
- 第 2 遍：裁出该行，用 `--psm 7` 识别。
- 第 3 遍：只在前两遍不一致时进行，同一裁行放大 1.5 倍后再用 `--psm 7` 识别。

比较时去掉空白和标点、忽略大小写。表决规则：
- 任意两遍一致：采用一致文字；
- 三遍互不一致，但某一遍的所有可读词置信度 ≥ 50、行均值 ≥ 文字阈值：采用该遍；
- 否则计为不确定行。

每一遍的文字都记在 `weak_line_verification` 里。注意：多遍一致只说明结果稳定，不等于正确（实测中“接入”被两遍一致地识别成“撑人”）。这正是 OCR 文本不作验收的原因。

## 覆盖与重建

- 可信行和不确定行（不确定行受上述上限约束）用其外圈背景的中位色覆盖；
- 背景图存为灰度，原图明显彩色时存为 RGB；
- 文字层按 OCR 行框写入，字体与颜色：
  - 中文用 PyMuPDF 内置 Droid Sans Fallback 嵌入子集；
  - 英文用 Base-14 Times；
  - 颜色取原墨色。
- 字号按段落宽度拟合。正文行（行高 ≤ 1.15 倍页面中位行高）字号不超过页面正文中位拟合字号的 1.03 倍，避免漏字导致字号虚高、被后端识别为标题。

## 资源

推荐合同：5 GiB RSS（任务进程树 RSS 之和，`resource_limits.RSS_CONTRACT`；原 3 GiB）、120 s/任务、重任务并发 1。

- OCR 阶段实测峰值约 0.31–0.50 GiB（RSS 合计，含 tesseract）；
- 随后的电子后端进程树 RSS 合计实测 2.5–3.3 GB（pdf2zh 子进程 2.0–2.6 GB；写时复制共享页按 RSS 重复计入，PSS 2.25–2.85 GiB）。旧 3 GiB 上限下 en-01 被内存门停止，rc.8 调为 5 GiB 后实测最高 3,336,155,136 B，余量约 1.89 GiB；
- 超限时按 `task_memory_limit` 停止并回收。
