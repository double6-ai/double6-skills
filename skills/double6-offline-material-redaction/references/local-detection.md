# 本地检测与人工确认

选择文件后自动执行本地检测，按类型列出疑似内容，并在原文或图片预览中标记。建议默认勾选；只有用户保留勾选的建议与人工补选会进入导出计划。用户可逐项取消、按类型选择、全部取消、点击「定位」核对，并补选漏掉的文字或区域。PDF 的检测遍历所有页，但不会替用户勾选“已逐页检查”。

## 检测范围

| 类型 | 当前依据 |
| --- | --- |
| 电话、邮箱 | 常见号码与邮箱格式、联系字段；排除紧邻订单号标签的普通手机号候选 |
| 身份证号、银行卡号 | 常见身份证号码结构（含 X）、银行卡校验与对应字段 |
| 姓名 | 姓名、联系人、收件人、申请人、负责人、Name 等带冒号字段 |
| 地址 | 地址、住址、Address 等字段 |
| 机构 | 公司、学校、工作单位等字段，或常见机构名后缀 |
| 账号、护照、出生日期 | 学号、工号、账户、护照号、生日等字段 |

这是规则与文字识别生成的疑似项。正文中没有字段提示的人名、非标准地址、外语实体、模糊文字、手写内容、人脸、签名及业务语义秘密可能未识别。没有命中不等于没有敏感信息。检测最多列出 200 项，超过会提示拆分材料。

文本类材料按值替换，同一个已勾选原文的全部出现一起处理，预览也标出这些出现；手动补选仍支持一行中的 `\n` 表示原文换行。图片/PDF 按所在页的所选区域处理。彩色半透明框用于核对，取消项仍以灰色虚线显示；导出才进行实色覆盖。PDF 的 OCR 词框可能包含邻近标签，需在预览确认覆盖范围。PDF 的建议会对齐完整字符，不能对齐的项不自动勾选，须人工调整。

## 本地 OCR

- macOS 优先调用系统 Vision，语言请求为简体中文、繁体中文与英文。首次使用需 Apple Command Line Tools 的 `swiftc`；可以正常安装 Command Line Tools 后再使用，不修改系统安全设置。辅助源码为 `scripts/ocr_vision.swift`，编译缓存位于 `~/.local/share/double6-redaction/ocr/`，按源码 SHA 与架构区分。
- Windows 使用本机 [Tesseract](https://tesseract-ocr.github.io/tessdoc/Installation.html) 与 `chi_sim`、`eng` 语言包。macOS 无可用 Vision 编译工具时也可使用 Tesseract。安装后使 `tesseract --list-langs` 列出所需语言；或设置 `REDACTION_TESSERACT` 为程序的绝对路径。
- 识别引擎和语言包需提前安装，处理时不下载。图片在内存中归一化、必要时缩小到最长边 3200 像素，经标准输入传入 OCR；返回结果通过内存管道接收，不生成材料临时图片。
- PDF 检测每页可见图像并结合文字层，覆盖纯扫描页和混合页的疑似内容。OCR 不向导出副本添加文字层，不等于选择图像化 PDF。

可用性查看：

```bash
python scripts/cli.py doctor
```

`ocr.available` 仅说明引擎具备调用条件；`macOS Vision` 的第一次调用还会实际编译。应使用自备的合成中文图片做一次端到端检测，核对文字、坐标、选择与导出。OCR 不可用、超时、仅启用英文或部分页失败时，页面明确显示检测不完整，已经取得的文字层建议仍可核对，也可手动补选。不要把失败当作“没有检出敏感信息”。

## 数据和导出

检测结果只存在本机服务会话与本机页面中，清空会话会一并释放，不写入服务日志。不要把真实原文、截图或检测词发给在线 Agent。Python 文档解析、系统 OCR 与外部 OCR 的系统级缓存不构成可保证彻底擦除的范围。

修改勾选、补选或输出选项会撤销旧下载并要求重新确认。导出继续复检已选词/区域、关键保留项和支持的隐藏载体，不承诺自动发现全部敏感信息，也不穷尽恶意 PDF 对象图。Word/PPT 等仍按原规则重建；PDF 默认保留批注，清除批注和图像化需分别明确选择。

非标准 PDF 缩放（例如部分 UserUnit 页面）或原格式已有复杂遮挡时，原生导出的严格像素复检仍可能拒绝；检测到候选不表示该文件一定能安全导出，不自动切换到图像化。
